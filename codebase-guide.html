How this codebase works

A full-stack research assistant. You upload plain-text sources, the backend chunks and embeds them, and a Gemini agent answers questions in a streamed markdown response grounded in those files and, optionally, Google Search.

FastAPI + uvicorn · port 8787 React 19 + Vite · port 5173 SQLite + Chroma + Gemini embeddings Python 3.12 · Node 22

01 — What it is

The product has two user actions and nothing else: upload files, then ask a question. There is no login, no conversation history, no document list, and no rendered markdown. The answer is streamed as raw text into a <pre>.

The interesting part is the backend agent. Gemini is not allowed to call tools by itself (backend/src/agent.py:140). The app streams tokens as they arrive, and when the model emits search_documents, the app embeds the query, reads Chroma, and feeds the chunks back for another turn. Google Search, when enabled, stays a server-side Gemini tool. Its links are collected from grounding metadata and appended as a footer.

Design choice worth remembering Embeddings are computed by Gemini and stored as raw vectors. Chroma is only the index (backend/src/vector_store.py:18-23). The collection is created with embedding_function=None and cosine space, so retrieval quality depends entirely on the embedding model and on using RETRIEVAL_DOCUMENT at ingest time and RETRIEVAL_QUERY at search time.

03 — Runtime and configuration

Settings load once, at import, from REPO_ROOT / ".env" (backend/src/config.py:6-22). REPO_ROOT is two parents above config.py, so the backend refuses a backend/.env. A relative DATA_DIR is rewritten to an absolute path under the repo (backend/src/config.py:25-26). Docker overrides this with DATA_DIR=/data and mounts ./data:/data (compose.yml:6-11).

How processes start

  • make run-local starts backend and Vite in parallel (Makefile:17-18).
  • Backend: uv run main → uvicorn.run("main:app", host="0.0.0.0", port=8787) (backend/src/main.py:79-80). One process, no worker count, no reload flag.
  • Frontend dev server defaults to Vite’s port 5173. CORS allows only http://localhost:5173 (backend/src/main.py:14-19).
  • Docker frontend is also the Vite dev server, with VITE_API_BASE_URL=http://localhost:8787 so the browser on the host calls the published backend port (compose.yml:24-28).
Import-time side effects Importing the app opens Chroma (vector_store.py:27), constructs ResearchAgent (agent.py:211), and refuses to start without GEMINI_API_KEY. Tests set the key and a temp DATA_DIR in backend/tests/conftest.py:4-6 before those modules load. There is no lifespan hook and no health route.

04 — Workflows

Both flows are request-scoped. Nothing is remembered between research calls except the files already written to SQLite, disk, and Chroma.

Upload

1

Browser builds multipart form

frontend/src/App.tsx:79-92 submits the selected FileList. frontend/src/api.ts:48-61 appends every file under the field name files. The file input only accepts text/* (App.tsx:119).

2

Route fans out with asyncio.gather

POST /api/sources (main.py:61-68) reads each upload and calls agent.ingest_file concurrently. One IngestError becomes HTTP 400. Other exceptions become HTTP 500 through the catch-all handler.

3

Each file is registered, chunked, embedded, indexed

See section 05. On success the row is ready. The HTTP body is only { uploaded: [{ name, size, type }] } — not ids, not chunk counts, not status.

Research

1

Browser posts JSON and reads the body as a stream

App.tsx:24-45 clears the previous answer, creates an AbortController, and appends each decoded chunk with a functional setMarkdown. api.ts:8-41 uses response.body.getReader() and a TextDecoder. This is not SSE. It is a plain text/plain body.

2

Route validates and returns StreamingResponse

Empty or whitespace-only questions are HTTP 400 (main.py:71-76). Otherwise the response media type is text/plain and the body is agent.stream_research.

3

Up to five model turns

Each turn streams text to the client. A search_documents call pauses the answer, runs retrieval, and starts another turn with the tool result appended. Web links are appended only on a turn that does not also call the document tool. Details are in section 07.

4

Failures after the stream has started are text, not status codes

agent.py:127-132 catches any exception inside the generator and yields \n\nResearch failed: …. The HTTP status is already 200, so the UI shows that sentence in the same panel as the answer. Errors before the stream starts (validation, empty question) surface as researchError because response.ok is false.

05 — Ingestion

ResearchAgent.ingest_file (agent.py:97-118) is the whole pipeline:

  1. Sanitize the filename with Path(filename).name. ., .., and empty names become upload.txt (vector_store.py:78-82). This blocks path traversal. It does not make names unique.
  2. Allocate uuid.uuid4().hex and insert a SQLite row with status processing (db.py:38-47).
  3. Decode bytes as UTF-8. Any UnicodeDecodeError becomes IngestError("file is not valid UTF-8 text") (vector_store.py:71-75).
  4. Split on whitespace into overlapping word windows (chunks.py:10-26). Blank input returns no chunks and the file fails with "{name} has no text".
  5. Write the original bytes to data/uploads/{doc_id}/{filename} (vector_store.py:29-32). This happens only after decode and chunking succeed, so a bad file leaves a failed row and no bytes.
  6. Embed every chunk with task type RETRIEVAL_DOCUMENT.
  7. Upsert into the sources collection. Ids are {doc_id}:{chunk_index}. Metadata is doc_id, filename, chunk_index, word_start (vector_store.py:35-51).
  8. Mark the row ready. On IngestError or any other exception, mark failed with str(exc) and re-raise.

There is an explicit unfinished hook: agent.py:98 says “Use hashing to check whether uploaded data already exists.” db.py still contains a migration that drops a content_hash column if it is present (db.py:23-34). Dedup was started and then removed. Re-uploading the same file always creates a new document id and a second set of chunks.

Chunking math

Words are text.split() — any whitespace, no sentence or paragraph boundaries. Step size is max(int(chunk_words * (1 - overlap)), 1). With the defaults, 500 words and 0.15 overlap, the step is 425 words, so neighboring chunks share 75 words. The loop stops once a window reaches the end, so the tail is not padded. The unit test (backend/tests/test_core.py:7-13) locks this in: 40 words, window 20, overlap 0.15 → starts at 0, 17, 34.

Embedding parallelism

agent.py:71-83 slices texts into batches of 100 and schedules every batch with asyncio.gather. A semaphore of 4 (_embed_slots) caps in-flight Gemini calls. Results are flattened in batch order, so chunk i stays aligned with vector i. _read_embeddings (agent.py:85-95) rejects a short response or an empty vector. The same path embeds a one-item query. The concurrency test (test_core.py:49-72) uses two batches and asserts they overlap in time and keep order.

Multi-file uploads

main.py:64 gathers one ingest_file per file. The route test (test_core.py:75-106) stubs ingest with a short sleep and asserts both run at once. asyncio.gather is called without return_exceptions=True. If one file raises, that exception is propagated immediately and the other uploads are not cancelled. A sibling file can finish, land in Chroma, and be searchable even though the HTTP response is an error and never lists it.

06 — Retrieval

search_documents (agent.py:120-125) strips the query, embeds it as RETRIEVAL_QUERY, and calls search_chunks_by_vector with settings.top_k. An empty query returns the string "No query was provided." and does not hit the index.

vector_store.py:54-68 queries Chroma with a single vector and formats each hit as: 

[filename chunk 0]
chunk text here

Hits are joined with a blank line. No distances are read, even though Chroma returns them. There is no score cutoff, no filter on doc_id or filename, and no join back to SQLite, so a chunk is searchable as soon as add_chunks returns — status ready is not consulted. zip(..., strict=False) silently drops extras if the document and metadata lists ever differ in length.

Citation format does not match the tool output The system prompt demands [filename:chunk_index] (agent.py:24-25). The tool returns [filename chunk N]. The model has to translate. Nothing in the backend checks that a citation refers to a real chunk or that the claimed fact is in that text.

07 — Agent loop

The prompt is two string constants concatenated at request time (agent.py:17-31 and agent.py:136):

  • Always search uploaded sources before answering. If nothing relevant was uploaded, say so.
  • Do not invent sources. Write markdown. Cite every upload as [filename:chunk_index].
  • If Google Search is on, use it for facts that are not in the files, and cite pages as [title](url).

Those first two bullets and the web bullet pull in different directions. “If nothing was uploaded, say so” can make the model refuse a question that Google Search could answer. The web addendum is simply appended, with no priority between corpus and web.

Tools

tools() (agent.py:60-64) always includes search_documents (agent.py:33-50), a single required string argument query. When google_search_enabled is true it also appends types.Tool(google_search=...) and a ToolConfig with include_server_side_tool_invocations=True (agent.py:66-69). Automatic function calling is disabled (agent.py:140) so document search stays in this process, where the app can interleave it with token streaming. Google Search still executes inside Gemini; the app only reads candidate.grounding_metadata.

One turn, then maybe another

_answer (agent.py:134-182) keeps a contents list that starts as a single user message. For each of at most five turns:

  1. Open generate_content_stream.
  2. For every chunk, take candidates[0]. Skip the chunk if there is no candidate.
  3. Collect web sources from grounding metadata into a list local to this turn (agent.py:190-200). Dedup is string equality of the markdown line.
  4. Walk parts. Keep every part. If it is a finished search_documents call (will_continue is false), record it. If it is non-thought text, yield it immediately. Thought parts are stored for the history but not streamed (agent.py:167).
  5. If there were no document-search calls: optionally yield a **Web sources** footer, and if the model wrote nothing, yield a fixed “couldn’t find an answer” sentence. Then return.
  6. If there were calls: append the model turn, run each call through _tool_result (sequentially, in a list comprehension of awaits — not gathered), append those responses as a user turn, and loop.

After five turns that all requested another search, the client receives I couldn't finish that research request. (agent.py:182). Any text already streamed on earlier turns stays on screen.

Web sources are dropped when the same turn also searches documents web_sources is created inside the turn loop (agent.py:147). The footer is yielded only in the if not calls branch (agent.py:171-176). If the model calls search_documents on a turn that also grounded with Google, those links are discarded before the next turn. Later turns start a fresh list and only see grounding from that later turn.

_query (agent.py:202-208) reads call.args["query"] and ignores anything that is not a string. _tool_result always responds with the name search_documents (agent.py:184-188). The function-call id is not copied onto the response part. That matches the current manual loop, and it is a fragile spot if the SDK starts requiring ids to pair calls with responses.

08 — Persistence

Three stores under DATA_DIR, all gitignored:

SQLite research.sqlite

One table, documents: id, filename, status, error, created_at (db.py:5-14). Status values used in code are processing, ready, failed. There is no read API. Connections are opened and closed per call, schema is executed every time, and the writes are synchronous inside async request handlers, so they block the event loop. Concurrent ingests can hit SQLite’s default lock.

Files and Chroma

Originals: uploads/{doc_id}/{safe_filename}. Index: a persistent Chroma client at data/chroma, collection sources, cosine HNSW, vectors supplied by the app. The client and collection are module globals created at import. That is fine for one uvicorn process. Several workers would each open the same on-disk index.

Nothing deletes a document. Nothing lists documents. A failed ingest keeps the SQLite row and, if failure happened after add_chunks, would also keep vectors. Today add_chunks is the last fallible step before mark_ready, so a failure inside mark_ready itself is the case that leaves searchable chunks with a failed row.

09 — HTTP API and errors

RouteRequestSuccessFailure
POST /api/sources multipart field files, one or more 200 JSON UploadResult 400 IngestError as plain text. 422 if the body is not valid multipart. 500 otherwise, body is str(exc).
POST /api/research JSON { "request": "..." } 200 text/plain stream 400 if the trimmed question is empty. Once streaming starts, errors are written into the body.

All three exception handlers return PlainTextResponse (main.py:43-57), which matches the frontend: it reads response.text() and throws new Error(text) (api.ts:15-17 and api.ts:64-66). The 500 handler returns the exception string to the browser. That is convenient in a tech test and too open for anything exposed.

There is no GET for sources, no delete, no health check, no request id, no upload size limit, and no rate limit. FastAPI’s default docs stay enabled at /docs.

10 — Frontend

frontend/src/main.tsx mounts App in React strict mode. App is one component and three panels: sources, request, streaming response (App.tsx:105-169). State is local useState. No router, no global store, no markdown library. The dependency list is React only (frontend/package.json).

  • API base URL is import.meta.env.VITE_API_BASE_URL or http://localhost:8787 (api.ts:1). It is baked in at Vite build/dev time. The browser calls it directly, so CORS must allow the page origin.
  • Research can be aborted (App.tsx:63-70). Abort during the request sets “Research request cancelled.” An abort that is not user-initiated is swallowed. Upload cannot be aborted.
  • The selected file list is derived from the FileList on every render (App.tsx:19-21). After a successful upload the input is not cleared, so the same selection can be submitted again and will be ingested as new documents.
  • The response panel is aria-live="polite" and shows either the accumulated string or a placeholder (App.tsx:163-167). Markdown syntax is visible as source, which the page copy states on purpose.

vite.config.ts only registers the React plugin. There is no proxy, so the frontend never hides the backend origin. Lint is oxlint; there is no frontend test script.

12 — Suggestions for improvements

These are changes to behavior that already exists: correctness, reliability, and how the current pieces fit together. New product surface is in the next section.

High

Make multi-file upload consistent

main.py:63-66 uses asyncio.gather without return_exceptions. One bad file fails the response while siblings keep running and may become searchable. Either ingest all files, return per-file success and failure, or treat the batch as a transaction: if any file fails, delete the chunks and rows created by the others before responding. The README already calls the second option out as missing (README.md:94).

High

Keep web sources across turns

Hoist web_sources out of the turn loop in agent.py:144-176, or merge grounding metadata into a request-level list and render the footer once, when the loop returns. Today a turn that both searches documents and uses Google Search throws the links away.

High

Pass distances through and stop citing weak hits

vector_store.py:56-68 drops Chroma distances. The prompt then says to always cite tool results (agent.py:24-25). A low-similarity neighbor is indistinguishable from a direct match, so the model is pushed to cite it. Return the distance, drop hits under a threshold, and tell the model it may abstain.

High

Align the citation contract

Tool text is [filename chunk N]. The required citation is [filename:chunk_index]. Emit the citation token in the tool result itself, and include doc_id so later checks do not depend on filenames, which are not unique.

Medium

Stop blocking the event loop on SQLite and Chroma

insert_document, mark_ready, add_chunks, and collection.query are synchronous and are called from async handlers. Under overlapping uploads that stalls embedding concurrency and can trip SQLite’s writer lock. Run those calls in asyncio.to_thread, use a single connection with WAL, or move ingest onto a worker. Also open the connection as a context manager instead of try/finally: close repeated in db.py:39-50 and db.py:62-70.

Medium

Bound Gemini calls

There is no timeout, no retry, and no backoff around embed_content or generate_content_stream. A hung embed holds an EMBED_WORKERS slot until the client gives up. Add a per-call timeout and limited retries for transient failures. Cap how many embed tasks are created: agent.py:72-73 schedules every batch at once and only then waits on the semaphore.

Medium

Tighten the prompt so corpus and web do not contradict each other

State an order: search uploads first; if the chunks do not support the claim, either abstain or use Google Search; never invent an upload citation for a web fact. The current concatenation (agent.py:136) says both “if nothing relevant was uploaded, say so” and “use Google Search for facts that are not in the files.”

Medium

Do not return raw exception text on HTTP 500

main.py:55-57 sends str(exc) to the client. Log the exception server-side and return a stable message. The in-stream Research failed: {exc} line (agent.py:132) has the same leak once the stream has started.

Medium

Fix chunking where whitespace splitting is the wrong unit

chunks.py:11 splits on whitespace. That works for English prose and splits identifiers, URLs, and CJK text poorly. It also cuts in the middle of sentences, which hurts both retrieval and citation. Prefer paragraph or sentence windows with the word count as a max size. The overlap math can stay; the test in test_core.py:7-13 would need updating if the splitter changes.

Medium

Run tool calls concurrently, and copy call ids

agent.py:179 awaits each _tool_result one after another. Independent queries can embed and search together under the existing semaphore. Include the function-call id on the response part so the manual loop stays valid if the SDK requires pairing.

Low

Smaller cleanliness items

  • Remove unused docling until PDF ingest exists, or the dependency installs a large unused stack in every image (pyproject.toml:8, backend/Dockerfile:17-18).
  • Wire mypy and coverage into make check. Strict mypy is configured and never run.
  • Replace the destructive content_hash drop (db.py:23-34) with a forward migration once dedup is real. Running that block today deletes the column on every connect if it exists.
  • Add Cache-Control: no-cache and X-Accel-Buffering: no on the research stream so proxies do not hold tokens.
  • Clear the file input after a successful upload (App.tsx:90-93) so a second click is an intentional re-ingest.
  • CORS is a single origin (main.py:16). Docker works only because the browser uses localhost:5173. A different host or port fails quietly in the browser.
  • Move ResearchAgent() and open_collection() behind a FastAPI lifespan so tests and --help-style imports do not need a live key and a writable data dir.
  • Use zip(..., strict=True) in vector_store.py:64 so a mismatched Chroma response fails loudly.

13 — What can still be implemented

The README table at README.md:80-94 is the project’s own backlog. The items below include that list and the gaps that show up once you follow a request through the code. None of these have a route, a UI, or a test today.

Listed in the README

Content-hash dedup

The TODO is agent.py:98. Hash the bytes before embed, store the hash on documents, and return the existing row when the hash matches. Skip Gemini and Chroma. Decide what “same content, different filename” should do. The old column-dropping migration has to be replaced, not reused.

Listed in the README

Background upload queue

Ingest currently lives inside the HTTP request, including every embedding batch. A queue (or even BackgroundTasks plus polling) would accept the file, return a document id, and let the UI show processing. SQLite already has that status and nowhere to read it.

Listed in the README

PDF and Office via docling

The library is installed and unused. decode_text is the only parser (vector_store.py:71-75), and the file input is accept="text/*". A parser step in ingest_file, chosen by content type, is the seam. Keep the rest of the pipeline on extracted text.

Listed in the README

Reranking

Retrieve a wider set than TOP_K, then rerank with a cross-encoder or a cheap model call before the string is handed to the agent. This belongs in search_chunks_by_vector or just above it, after distances exist.

Listed in the README

Hybrid retrieval and filters

Metadata already stores doc_id and filename (vector_store.py:42-49) but collection.query never filters. Add an optional filename or document filter on the tool, plus a lexical index (BM25 or SQLite FTS) merged with the vector hits. Useful when the user names a file.

Listed in the README

Observability

No logs, no request id, no token counts. The README suggests structured logs and Langfuse or OpenTelemetry around embed latency, generation latency, and cost. The natural spans are ingest_file, _embed_batch, each agent turn, and search_documents.

Listed in the README

Evaluation harness

README.md:100-126 already specifies the split: recall@k for retrieval, citation accuracy and faithfulness for generation, abstention on questions that are not in the corpus. A golden file of (question, expected chunk ids) can run against the fake-embedder style used in tests, with a separate recorded-Gemini job for drift. make test does not do this.

Listed in the README

Safety and operations

Rate limits, a max upload size, authentication, and all-or-nothing multi-file behavior. Also missing, and cheap: a body size limit on UploadFile, a max question length, and refusing to start the stream for an empty corpus with a clear message instead of a model round-trip.

Visible in the product, not in the README table

API + UI

List, inspect, and delete sources

The UI forgets uploads on refresh. SQLite has every row and nobody selects from it. A GET /api/sources can return id, filename, status, error, created time, and chunk count. DELETE /api/sources/{id} should remove the row, the upload directory, and the Chroma ids {doc_id}:*. Without delete, the only fix for a bad or duplicate file is to wipe data/.

Agent

Conversation memory

Each research call starts a new contents list with one user message (agent.py:135). “Tell me more about the second point” has no prior answer to refer to. A session id plus stored turns would make follow-ups work. Keep retrieval on every new factual question so memory does not replace citations.

Agent

Citation checking before the stream ends

After the final turn, parse [filename:chunk_index] tokens, confirm the pair exists in Chroma, and optionally verify a quoted span. Strip or flag citations that do not match. This is the enforcement version of the instruction at agent.py:23-25, which is currently honor-system only.

UI

Render markdown, and show sources as they are used

The response panel prints the raw stream (App.tsx:165-167). A sanitizing markdown renderer would match what the prompt asks the model to write. A side list of retrieved chunks, filled when the backend emits a small structured event before the prose, would make citations checkable. That implies a real stream protocol (SSE or newline-delimited JSON) instead of undifferentiated text/plain.

API

Health and readiness

compose.yml uses depends_on with no healthcheck, so the frontend can start before the API is listening. GET /health can report process up; GET /ready can check that the data directory, SQLite, and Chroma open. The frontend container’s command also runs npm install on every start (compose.yml:28) even though the image already installed dependencies.

Retrieval

Per-document questions and “what did I upload?”

The agent cannot list filenames unless they happen to be in the top-k chunks. A second tool, list_documents, reading SQLite, would let the model answer inventory questions without pretending a vector search is a catalog.

Tests

The agent loop itself

Stub generate_content_stream to yield a function call and then a text answer. Assert the tool result is appended, text is streamed, the web footer appears, the footer survives a mixed turn, the fifth turn yields the give-up sentence, and an empty request is HTTP 400. Those are the branches in agent.py:144-182 and main.py:73-75, and they are currently untested.

A sensible order if this were the next sprint Fix multi-file failure handling and the dropped web-source footer first — both are wrong with the code as it stands. Then add list/delete so the corpus is operable, content-hash dedup so re-uploads stop polluting search, and a retrieval eval so chunk size and TOP_K can be changed with evidence. PDF parsing, reranking, and a job queue are larger and sit cleanly on top of that.
